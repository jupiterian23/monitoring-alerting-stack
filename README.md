# 📊 Monitoring & Alerting Stack

> 🚀 **An end-to-end observability project for monitoring, visualizing, and alerting on a containerized application.**

This project demonstrates what happens **after deployment** — collecting application metrics, visualizing system behavior, detecting failures, and routing alerts automatically.

## 🎯 Project Objective

The goal of this project is to build a small but realistic **observability stack** capable of:

✅ Monitoring an application
✅ Collecting metrics
✅ Visualizing metrics
✅ Detecting application failures
✅ Generating alerts
✅ Routing alerts through Alertmanager
✅ Delivering alerts to a webhook
✅ Running everything through Docker Compose

# 🚨 Alerting

The project uses Prometheus alert rules and Alertmanager.

## Alert Rule

```text
ApplicationErrorsDetected
```

The rule detects an increase in application errors:

```promql
increase(app_errors_total[5m]) > 0
```

The condition must remain active for:

```text
30 seconds
```

before the alert fires.

### 🔄 Alert Flow

```text
❌ Application Error
        │
        ▼
📈 app_errors_total increases
        │
        ▼
🔍 Prometheus evaluates rule
        │
        ▼
🚨 ApplicationErrorsDetected
        │
        ▼
📨 Alertmanager
        │
        ▼
📡 POST /alerts
        │
        ▼
✅ Flask receives alert
```

Alert configuration:

```text
prometheus/alerts.yml
```

Alertmanager configuration:

```text
alertmanager/alertmanager.yml
```

# 💼 Interview Talking Points

### ❓ How did you monitor the application?

The Flask application exposes a `/metrics` endpoint using the Prometheus Python client. Prometheus periodically scrapes this endpoint and stores the metrics as time-series data.

### ❓ How did you visualize the metrics?

Grafana uses Prometheus as its datasource and displays application health, request volume, error rate, and request latency on a dashboard.

### ❓ How did you implement alerting?

Prometheus evaluates an alert rule based on the application error metric. When the configured condition remains active long enough, Prometheus sends the alert to Alertmanager.

### ❓ How did you test the alert pipeline?

The `/error` endpoint intentionally generates HTTP 500 responses and increments `app_errors_total`.

Prometheus detects the metric increase, the alert rule fires, Alertmanager receives the alert, and Alertmanager sends a webhook request to the Flask `/alerts` endpoint.

### ❓ What did you troubleshoot?

During development, Alertmanager initially failed to start because its configuration was missing the required root route. After correcting the configuration, the complete Prometheus → Alertmanager → webhook pipeline was verified.
